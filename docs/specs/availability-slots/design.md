# Availability slots — Design

> References like _(Req 2.5)_ point at [`requirements.md`](requirements.md).

## Overview

Three decisions shape the feature:

- **Slots are planned by a pure domain function.** `SlotPlanner.Plan` takes a branch (with its schedule), a service type, a date range, a capacity and "now", and returns candidate slots. All the calendar arithmetic — local dates, time zones, DST gaps, slots that run past closing, slots in the past — lives in one function with no I/O, so every rule in Requirement 2 is a unit test against it. The handler only loads, filters overlaps, and saves.
- **Times are stored in UTC, dates in local time.** A slot stores `StartUtc`/`EndUtc` because instants are what Booking compares and what events carry. It also stores `LocalDate` because "the slots on 5 October in Colombo" is a local-date question, and turning it into a UTC range on every search would spread the time-zone logic. `LocalDate` is fixed at generation time, which is correct because a slot never moves.
- **"Now" comes from `TimeProvider`.** Handlers take `TimeProvider` (registered as `TimeProvider.System`) so that tests can pin the clock, which Req 2.4 and 3.1 depend on.

## Components

### Endpoints

| Verb / route | Controller action | Authorization | Dispatches | Req |
|---|---|---|---|---|
| `PUT /api/branches/{id:guid}/schedule` | `BranchesController.SetSchedule` | `AdminPolicy` | `SetBranchScheduleCommand` | 1 |
| `POST /api/slots/generate` | `SlotsController.Generate` | `AdminPolicy` | `GenerateSlotsCommand` | 2 |
| `GET /api/slots/available?branchId=&serviceId=&date=` | `SlotsController.GetAvailable` | `AllowedOriginsPolicy` | `SearchAvailableSlotsQuery` | 3 |

`AddControllers().AddJsonOptions(...)` registers `JsonStringEnumConverter` in Availability, so that `DayOfWeek` is written and read as `"Monday"` rather than `1`. `DateOnly` binds from `yyyy-MM-dd` and `TimeOnly` serialises as `HH:mm:ss`.

### Commands, queries and handlers

| Request | Handler | Returns |
|---|---|---|
| `SetBranchScheduleCommand(Guid Id, string TimeZoneId, IReadOnlyList<WorkingHoursRequest> WorkingHours)` | validate → `GetForUpdateByIdAsync` → `Branch.SetSchedule` → commit | `Result<BranchResponse>` |
| `GenerateSlotsCommand(Guid BranchId, Guid ServiceTypeId, DateOnly FromDate, DateOnly ToDate, int Capacity)` | see below | `Result<GenerateSlotsResponse>` |
| `SearchAvailableSlotsQuery(Guid BranchId, Guid ServiceTypeId, DateOnly? Date)` | validate → branch and service type active? → `SearchAvailableAsync` | `Result<List<SlotResponse>>` |

`GenerateSlotsCommandHandler`:

1. Validate (Req 2.7) → 400.
2. Load the branch and the service type with no tracking. If either is missing → 404 (Req 2.8). If either is inactive → 409 "Branch '{Code}' is inactive." or "Service type '{Code}' is inactive." (Req 2.9). If the branch has no time zone or no working hours → 409 (Req 2.10).
3. `SlotPlanner.Plan(branch, serviceType, from, to, capacity, now)` → candidates.
4. `ListOverlappingAsync(branchId, serviceTypeId, firstCandidate.StartUtc, lastCandidate.EndUtc)` loads the existing slots in that window. Candidates that overlap any existing slot (`a.Start < b.End && b.Start < a.End`) are dropped and counted as skipped (Req 2.6).
5. `AddRangeAsync` → `SaveChangesAsync`. `DuplicateSlotException` → 409 "Slots for this branch and service type were generated by a concurrent request. Try again." (Req 2.11).
6. Return `{ CreatedCount, SkippedCount }`.

### `SlotPlanner`

```csharp
public static IReadOnlyList<Slot> Plan(
    Branch branch, ServiceType serviceType, DateOnly fromDate, DateOnly toDate, int capacity, DateTime nowUtc)
```

For each date, the planner finds that weekday's `WorkingHours`. It walks start minutes from `OpensAt` in steps of `DurationMinutes`, while `start + duration <= ClosesAt`, counting in minutes since midnight so that nothing wraps past midnight. For each start it:

- skips the start if `TimeZoneInfo.IsInvalidTime(localStart)`, because the time does not exist on that date (Req 2.5);
- sets `startUtc = TimeZoneInfo.ConvertTimeToUtc(localStart, zone)`, which resolves an ambiguous local time to standard time (Req 2.5);
- sets `endUtc = startUtc + duration`, so a slot always lasts the service's real elapsed duration, even across a clock change;
- skips the slot if `startUtc <= nowUtc` (Req 2.4).

### Validation

| Validator | Rules |
|---|---|
| `SetBranchScheduleCommandValidator` | `TimeZoneId` resolves with `TimeZoneInfo.TryFindSystemTimeZoneById` **and** `HasIanaId` (an IANA id works the same on Windows and Linux; a Windows id would not); `WorkingHours` not null, days distinct; each entry: `DayOfWeek` is in the enum, `OpensAt`/`ClosesAt` match `^([01]\d|2[0-3]):[0-5]\d$`, `OpensAt < ClosesAt` |
| `GenerateSlotsCommandValidator` | ids not empty; `FromDate <= ToDate`; `ToDate.DayNumber - FromDate.DayNumber < 31`; `Capacity` 1–100 |
| `SearchAvailableSlotsQueryValidator` | ids not empty; `Date` not null |

## Data model

### Branch schedule

```csharp
public sealed class Branch
{
    // ...existing members...
    public string? TimeZoneId { get; private set; }
    public IReadOnlyList<WorkingHours> WorkingHours { get; }      // backed by a private List<WorkingHours>
    public void SetSchedule(string timeZoneId, IEnumerable<WorkingHours> workingHours);
}

public sealed class WorkingHours
{
    public DayOfWeek DayOfWeek { get; private set; }
    public TimeOnly OpensAt { get; private set; }
    public TimeOnly ClosesAt { get; private set; }
}
```

`WorkingHours` is an EF Core owned collection (`OwnsMany`) in a `BranchWorkingHours` table, keyed by `(BranchId, DayOfWeek)`. `SetSchedule` updates the collection **in place**. It changes the times of days that remain, removes days that are no longer listed, and adds new ones. It never removes and re-adds the same key, which EF would reject. The constructor and `SetSchedule` throw `ArgumentException` for a duplicate day or `OpensAt >= ClosesAt`. The validator catches these first, so the exception means a bug.

`Branches` gains a nullable `TimeZoneId` column (max 64).

### Slot

```csharp
public sealed class Slot
{
    public Guid Id { get; private set; }
    public Guid BranchId { get; private set; }
    public Guid ServiceTypeId { get; private set; }
    public DateOnly LocalDate { get; private set; }
    public DateTime StartUtc { get; private set; }
    public DateTime EndUtc { get; private set; }
    public int Capacity { get; private set; }
    public int ReservedCount { get; private set; }    // always 0 until FR-AVL-005
    public DateTime CreatedAtUtc { get; private set; }
    public int AvailableCapacity => Capacity - ReservedCount;
}
```

`Slots` table: foreign keys to `Branches` and `ServiceTypes` with `Restrict` on delete; unique index `IX_Slots_BranchId_ServiceTypeId_StartUtc` (Req 2.11); index `IX_Slots_BranchId_ServiceTypeId_LocalDate` for search. Migration `AddSchedulesAndSlots` covers both the schedule and the slots.

## Responses

- `BranchResponse` gains `TimeZoneId` and `WorkingHours` (`WorkingHoursResponse(DayOfWeek, TimeOnly OpensAt, TimeOnly ClosesAt)`, Monday first).
- `GenerateSlotsResponse(int CreatedCount, int SkippedCount)`.
- `SlotResponse(Id, BranchId, ServiceTypeId, DateOnly Date, DateTime StartAtUtc, DateTime EndAtUtc, TimeOnly LocalStartTime, TimeOnly LocalEndTime, int Capacity, int AvailableCapacity)`. The search handler computes the local times from the branch's zone.

| Branch or service type missing | 404 | 1.4, 2.8, 3.4 |

## Testing strategy

| Test class | Covers |
|---|---|
| `BranchScheduleTests` | `SetSchedule` replaces, updates in place and removes days; guards against duplicates and inverted times; ordering in the response |
| `SlotPlannerTests` | Back-to-back slots inside the hours; the last slot never runs past closing; closed days get no slots; past slots skipped; local → UTC with a fixed offset (`Asia/Colombo`, +05:30); a DST spring-forward gap and a fall-back day (`Europe/London`); a range spanning several weeks |
| `SetBranchScheduleCommandValidatorTests`, `GenerateSlotsCommandValidatorTests` | Every rule at its boundary, including an unknown and a Windows-style time zone id |
| `GenerateSlotsCommandHandlerTests` | 404 and 409 paths write nothing; overlap filtering counts skips; a second run creates nothing; concurrent-race 409 |
| `SearchAvailableSlotsHandlerTests` | 404 for missing or inactive branch and service type; local times computed in the branch zone; the repository is asked for slots after "now" |
| `SlotsControllerTests`, additions to `BranchesControllerTests` | Status mapping and each action's policy |

The repositories and the migration are exercised by hand against a local PostgreSQL, as in the previous Availability specs.
